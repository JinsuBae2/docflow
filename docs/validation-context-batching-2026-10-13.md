# 큰 맥락 분할 분석 검증 — #19

기준: 9af046b. 브랜치: feat/19-context-batching.

## 구현 범위

- 저장된 등록 문서를 문서/섹션/원문 범위/revision으로 나누고 제목·본문의 요청 관련도를 우선한다. 일반 대화에서도 큰 관련 문서는 일치하는 섹션을 검색하며 부분 전송을 표시한다.
- 기본 32,768 맥락 / 8,192 출력 / 8,192 지침·schema 여유를 분리한다. JSON 직렬화와 UTF-8 바이트를 기준으로 보수적으로 추정한다. 모델의 실제 한도를 확인한 값으로 표시하지 않는다. 분석별 맥락 20,000–200,000, 출력 1,024–8,192 범위에서 명시 설정한다.
- 기본 모델 설정이면 모델 목록에서 실제 기본 모델 ID를 조회하여 계획에 고정한다. 제공자·모델·예산·schema·지침·입력 내용이 같은 완료 묶음만 재사용한다.
- 본문 묶음 뒤 기존 수동/AI/Markdown 연결의 양쪽 관련 근거를 함께 검토한다. 앵커가 있으면 해당 섹션을 사용한다. 누락 링크·읽기 실패·제외로 빠진 연결 근거를 알린다.
- 분석 계획·진행·결과를 SQLite에 저장하고 완료 묶음을 보존해 취소/앱 재시작 후 재개한다. 문서 변경·삭제, 새 초안, 프로젝트 목표·결정·처리 이력·수동 연결 변경은 기존 계획을 무효화한다. 변경하지 않은 문서의 묶음은 새 계획에서 재사용한다.
- 제안 등록은 request ID와 트랜잭션으로 중복을 막는다. 등록 직전 중단되어 저장된 응답이 있으면 AI 재호출 없이 복원한다. 실패·취소·재시도도 각각의 사용량 기록을 남긴다.
- scopedSourceId가 있는 수정은 저장된 근거 범위만 교체한다. 전체 revision/발췌 원문/초안/관리 문서 식별자를 확인하고 journal로 저장하며 비선택 본문·CRLF를 보존한다. 발췌 전후 차이와 원문 문서로 이동하는 근거를 표시한다.
- 작은 프로젝트 관계 검토는 기존 미리보기를 유지하며, 기존 30,000자 필터로 일부 문서를 자동 제외하지 않는다. 큰 프로젝트는 분석 창으로 안내한다.

## 제한

- 토큰 추정은 정확한 tokenizer 결과나 계정의 잔여 한도가 아니다. 실제 제공자의 더 작은 한도/네트워크 오류는 완료하지 않은 묶음의 오류로 보존한다. Codex의 출력은 수신 후 로컬 크기를 검사하며 서버 측 hard cap을 보장하지 않는다.
- 문서 본문 전체를 처리하지만 연결 통합은 기존 관계/링크 양쪽의 관련 발췌에 기반한다. 링크 없는 모든 문서 쌍을 전수 비교하거나 프로젝트 전체를 한 모델 입력에 재통합하지 않는다.
- 지침·결정·거절 이력 자체가 설정한 입력 예산을 넘으면 조용히 버리지 않고 계획 오류와 예산 조정을 안내한다.
- 실제 개인 문서·유료 AI 추론·DMG 재생성·자동 업데이트는 수행하지 않았다. macOS·Windows CI는 PR Checks에 별도로 기록한다.
