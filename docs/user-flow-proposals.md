# AI 유저플로우 제안

**사용자 흐름 → 유저플로우**에서 **AI로 플로우 생성** 또는 저장된 흐름의 **AI로 흐름 수정**을 선택한다. 맥락 확인 창에서 전달할 문서와 요청 내용을 검토하고 예상 입력 사용량을 확인한 뒤 요청한다. 사용량은 UTF-8 바이트를 이용한 보수적 추정이며 실제 모델 토큰 수와 다를 수 있다. Claude 출력 상한은 기본 8,192 토큰이고 Codex 출력은 CLI 설정에 따른다.

제안 목록에서 **캔버스 Diff 검토**를 누르면 초록색 추가, 주황색 수정, 붉은색 반투명 삭제를 원본과 함께 확인할 수 있다. 변경 속성 패널은 라벨, 부모 그룹, 분기 포트 및 연결 대상 등의 이전/이후 값을 표시한다. 근거 배지를 누르면 해당 문서/섹션으로 이동한다. 추정 단계는 AI 추정 배지를 표시한다.

**플로우 수락**은 요청 시점 플로우 revision과 근거 문서 revision이 현재 값과 일치할 때만 저장한다. 기존 같은 부모 노드 좌표를 유지하고 신규/부모 이동 노드만 ELK Worker로 배치한다. 삭제 ghost도 배치 공간을 예약하여 신규 노드가 삭제 표시를 가리지 않게 한다. ghost/Diff 플래그는 저장하지 않는다.

**플로우 거절**은 원본 파일을 변경하지 않는다. 사유 없이 거절하면 검토가 끝나며, 사유를 입력하면 기존 피드백 대화로 보완안을 요청한다. 실패한 후속 답변은 제안 목록에서 재시도할 수 있다. 전달했던 섹션 범위는 후속 요청에서도 유지한다.

JSON 원자 저장과 제안 수락 상태는 기존 `.workspace/operations` 복구 저널을 함께 사용한다. 저장 후 종료되더라도 프로젝트를 다시 열면 수락 상태가 복구되며, 외부 변경이 발견되면 덮어쓰지 않는다.

기존 문서·관계 제안과 유저플로우 제안은 별도 출력 스키마·지침을 사용하므로 기존 프로젝트 분석 예산을 늘리지 않는다. 기본 요청 맥락의 60,000자 제한과 문서 초안/제외 정책은 기존과 동일하다. 큰 입력은 관련 원문 섹션을 예산 안에서 자동 발췌하고 선택·제외 내역을 표시한다. 원문 범위와 revision을 보존하며 근거가 없으면 전송을 차단한다. 실제 AI가 연결되지 않으면 가짜 테스트처럼 생성할 수는 없으며 제공자 오류가 표시되고 원본은 유지된다.
