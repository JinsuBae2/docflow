# 문서 다이어그램과 유저플로우 작업 공간 검증

이슈 #44. 기존 Mermaid/React Flow, 문서 저장·제안 수락 계약을 유지한다.

## 변경

- 문서 다이어그램 생성과 사용자 흐름 정리는 아이디어 상담 상태와 관계없이 문서 기반 맥락 검토를 연다. 근거를 모두 제외하면 전송하지 않는다. 구조화된 유저플로우 생성·수정은 기존 전용 schema를 유지한다.
- Mermaid ERD를 미리 보며 원문 편집은 문서에서 수행한다. 지원하지 않는 형식·읽기 전용 사유·문법 오류를 구분하고 실행 링크·HTML·설정 지시문 차단은 유지한다.
- 문서 다이어그램과 유저플로우의 역할을 구분한다. 목록 접기, 남은 공간을 사용하는 캔버스, SVG 크기에 실제로 적용되는 확대/축소와 화면 맞춤을 제공한다.
- 확대 보기는 자식 컴포넌트를 재마운트하지 않는다. 선택·배율·초안·수동 좌표를 유지하고 Escape 종료·포커스 복원·원문 코드 summary까지 Tab 접근을 검증한다.

## 검증 결과

- lint, format:check, typecheck, 프로덕션 빌드 통과.
- `npm test`: 176개 통과, 실계정 관련 6개 건너뜀.
- `npm run test:e2e`: 25개 통과. 임시 프로젝트와 가짜 AI 제공자만 사용했다.
- 800×700, 1280×800, 1600×1050의 기본/확대 영역, 실제 SVG 확대, ERD 렌더링, 문서 근거 없는 전송 차단, Mermaid/유저플로우 초안 보존 및 기존 수동 좌표 유지 확인.
- DMG 복사본의 동일 기능 E2E 2개 통과. DMG 체크섬 VALID, 빌드 파일 66개 일치, 상대 프레임워크 링크 14개 정상. macOS ARM64, 버전 0.1.0 유지.
- 비식별 합성 화면: `docs/images/diagram-workspace-expanded.png`.

빌드와 병행한 최초 단위 테스트에서는 기존 대용량 입력 테스트 2개가 5초 제한에 걸렸다. 빌드 종료 후 워커 제한 실행과 기본 `npm test` 모두 통과했다. 최초 전체 E2E의 이전 버튼 이름 참조 1개를 갱신한 뒤 전체 25개가 통과했다.

첫 macOS/Windows CI에서는 기존 다이어그램 탐색 E2E가 목록이 항상 열려 있다고 가정해 실패했다. 800×700에서 같은 실패를 재현한 뒤, 목록 펼치기·항목 선택·목록 접기를 실제 사용자 동작으로 수행하도록 보완했다. 편집 검증은 1600×1050에서 수행한다. 앱 코드 변경 없이 CI의 작은 화면 조건을 테스트에 반영했다.

## 리뷰와 범위

별도 읽기 전용 리뷰에서 Critical/Important 없음, 원문 summary의 키보드 접근 누락 1건 발견. 실패 테스트로 재현한 뒤 포커스 순환 대상을 보완해 통과했다. E2E에서 툴팁의 Escape 선점도 발견하여 확대 보기의 dialog 역할과 종료 회귀 테스트로 해결했다.

문서·DB 스키마 변경, 실제 AI 생성, 자동 업데이트 및 공개 Release는 수행하지 않았다. Windows 실기기에서의 시각적 검증은 수행하지 않았으며 Windows/macOS CI 결과는 PR Checks에서 확인한다. 기존 작업 환경의 전용 브랜치를 사용하고 stash는 보존했다.
