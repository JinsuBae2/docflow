# AI 토큰과 한도 표시 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 제공자가 보고한 요청 토큰과 계정 한도, 확인 불가 사유를 표시한다.

**Architecture:** 제공자의 사용량 이벤트를 정규화하고 요청 ID별 DB 기록을 갱신한다. 계정 한도는 독립적인 읽기 전용 조회 계약으로 제공한다.

**Tech Stack:** Electron, TypeScript, React, SQLite, Vitest, Playwright.

**Spec:** [../specs/2026-10-13-project-ai-workflows-design.md](../specs/2026-10-13-project-ai-workflows-design.md)

## Review Focus

- 중복 누적 이벤트와 캐시 토큰 → 이중 합산 방지

### Task 1: 사용량 정규화와 저장

Files: `src/main/ai/usage.ts`(신규), `src/main/ai/provider.ts`, `src/main/ai/codex-provider.ts`, `src/main/ai/claude-provider.ts`, `src/main/project/store.ts`, `src/main/ipc.ts`, `src/shared/contracts.ts`, `tests/unit/usage.test.ts`(신규), 제공자 integration 테스트.

Interfaces: `UsageReport { inputTokens:number|null, outputTokens:number|null, cachedInputTokens:number|null, cacheWriteInputTokens:number|null, totalTokens:number|null, reason?:UsageReason }`; `UsageReason`은 no_history/unsupported/auth_mode/auth_required/network/missing_response/invalid_response를 구분한다. AiEvent에 usage 이벤트를 추가하고 요청 ID별 최신값으로 upsert한다. `AiProvider.getUsageLimits()`는 `provider`, `checkedAt`, `windows`, `reason?`를 반환한다. 각 window는 id·이름·단위·limit/remaining 또는 remainingPercent·resetsAt을 가진다.

- [ ] 실제 생성 프로토콜 형태로 Codex 누적 이벤트·다중/단일 한도, Claude 캐시 포함 usage·헤더, 값 누락/음수/NaN, 실패 응답의 usage, 같은 요청 재전달의 upsert 테스트 작성.
- [ ] `npx vitest run tests/unit/usage.test.ts tests/integration/codex-provider.test.ts tests/integration/claude-provider.test.ts` → 실패 확인.
- [ ] token usage와 rate-limit 헤더를 안전하게 파싱한다. Codex 요청은 스레드 total의 최신값을 사용한다. 실패/취소 이후에도 확인된 보고값을 보존한다. 조회 오류는 정규화된 reason으로 반환하고 비밀정보를 노출하지 않는다.
