## 제품 요구사항

- 등록 프로젝트에서 docs 후보와 하위 Markdown을 발견해 목록/중복/지원 사유를 보여주고 사용자 선택 후 등록한다. 취소는 무변경이다. 파일·폴더 직접 추가도 지원한다.
- 기존 프로젝트 문서는 원본 상대 경로를 연결하며 최초 등록으로 본문을 바꾸지 않는다. 기존 앱 관리 문서와 이력은 유지한다. 명시적 저장은 원본 대상과 충돌 상태를 표시한다.
- Markdown AST로 상대 링크·참조형 링크·파일 앵커·내부 앵커를 해석한다. 원문 링크/직접 관계/AI 제안 출처를 구분하고 파생 링크만 재색인한다. 프로젝트 밖 파일과 위험 URL 경계를 유지한다.
- 관계 지도에서 핸들 드래그 후 유형을 선택한다. 기존 main 저장과 중복·자기 연결 검증을 재사용하고 키보드 대체 경로를 제공한다.
- 프로젝트 흐름 보기는 여러 문서/블록을 제목·섹션별로 탐색한다. 기존 흐름은 AI 없이 표시하고 원문으로 이동한다. Mermaid flowchart/graph 외 sequence/state를 단계적으로 지원한다.
- 기본 흐름 시각 편집은 표현 가능한 부분집합을 대상으로 하며 복잡한 기존 문법을 손실시키지 않는다. 다른 형식은 별도 어댑터로 다룬다.
- 큰 AI 맥락은 제목/섹션/링크 색인, 관련 근거 우선 검색, 입력·출력 예산, 분할·통합·취소·재개·캐시로 처리한다. 출처 ID/revision과 제외 범위를 보존하며 발췌를 전체 문서로 덮어쓰지 않는다.

## 코드 가독성 — 첫 PR #14

- Prettier: 들여쓰기 2칸, 작은따옴표, 세미콜론, LF, printWidth 100, trailingComma all.
- 소스·테스트·스크립트·개발 설정을 정리한다. 기존 문서/예제/생성된 라이선스 원문/빌드/개인 데이터는 제외한다.
- ESLint flat config로 JS와 TS/TSX의 구문·기본 오류를 검사하고 TypeScript 7의 tsc를 타입/미사용 선언 검사의 기준으로 유지한다.
- 현재 typescript-eslint 8.71.2의 TypeScript peer 범위는 >=4.8.4 <6.1.0이다. 컴파일러 변경 대신 Babel 구문 파서를 사용한다. 타입 정보 기반 lint는 이 단계의 범위가 아니며 지원 도구가 준비되면 강화한다.
- 기능·저장 형식·API·Hook 의존성 변경은 이 PR에 섞지 않는다. 기계 포맷의 실행 AST 동일성을 검사한다.
- lint/format/format:check 명령과 기존 macOS·Windows CI 검사를 연결하고 문서화한다.

## 공통 검증과 경계

타입 검사·가까운 회귀 테스트·빌드·관련 Electron E2E와 합성 캡처로 검증한다. 개인 문서·DB·키를 사용하지 않는다. AI 출력은 사용자 수락 전 제안이며 원본·초안·거절 이력을 보존한다. 실제 유료 추론은 일반 테스트에 포함하지 않는다.
