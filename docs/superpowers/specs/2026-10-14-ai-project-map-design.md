# AI 프로젝트 관계 지도 설계

상태: 사용자와 합의한 방향을 상세화한 검토용 설계. 구현은 시작하지 않는다.
기준 코드: main / 9d5209b. 관련 구현: ProjectGraph.tsx, layout.ts, 문서 등록, AnalysisService.

## 목적과 합의

docs를 등록한 사용자가 AI에게 문서의 내용을 분석시켜 프로젝트의 문서 구조와 의미 관계를 한 화면에서 이해하고 직접 배치를 조정한다. AI와 플랫폼이 지도를 구성하며 Mermaid 문법 작성은 필요하지 않다.

- 기본 화면은 왼쪽 프로젝트 루트 → 가운데 등록 문서 → 오른쪽 문서별 소제목/주제의 3열이다.
- 문서·섹션 카드는 직접 이동하고 위치를 프로젝트별로 보존한다. 선은 카드 이동을 따라가며 다른 카드를 통과하지 않는다.
- 선에는 ‘원문 연결’ 대신 ‘구현’, ‘설계 근거’, ‘선행 조건’, ‘참조’ 등 관계의 의미를 표시한다.
- 오른쪽 위에 화면 이동·확대에 영향을 받지 않는 접이식 범례를 둔다.
- 실제 문서에 있는 제목과 AI가 본문에서 요약한 주제는 구분한다. AI가 원문에 없는 제목을 실제 섹션처럼 만들지 않는다.

## 접근 방식과 선택

1. Mermaid 코드 생성: 기존 렌더러를 쓰기 쉽지만 자유로운 카드 위치 저장·장애물 회피·세밀한 원문 연결에 불리하다.
2. **ReactFlow 구조 지도 + 구조화한 AI 분석 + 독립 배선 모듈: 권장.** 기존 캔버스와 분할 분석을 활용하면서 좌표·근거·관계 의미를 플랫폼이 관리한다.
3. 문서 전체를 한 번에 보내 그림 생성: 초기 구현은 작지만 큰 문서·재개·근거 검증에 맞지 않는다.

두 개의 PR로 나눈다. A는 AI 없이도 쓸 수 있는 지도·배치·배선, B는 등록 직후 AI 생성과 검토다. 새로운 유료 서비스나 다이어그램 실행 엔진은 도입하지 않는다.

## 사용자 흐름

1. 폴더 열기/드롭 → docs 탐색 → 등록할 원본 문서를 사용자가 선택한다. 수동 파일·폴더 등록과 Markdown 가져오기도 같은 완료 경로를 사용한다.
2. 새 문서가 실제로 등록된 뒤 다음 안내를 한 번 보여준다. 등록 취소·중복 등록·단순 재실행에는 띄우지 않는다.

   **AI로 관계 지도를 생성하시겠습니까?**
   등록한 문서의 내용을 분석해 프로젝트·문서·소제목의 구조와 관계를 그립니다. 파일 크기와 개수에 따라 AI 사용량이 증가할 수 있습니다.
   버튼: **나중에 / 전송 범위 확인**.

3. 전송 범위에서 프로젝트의 등록 문서를 확인한다. 새 문서는 강조하고 기존 문서 포함 여부를 조정한다. 초안·제외 문서는 보내지 않는다. 제공자·모델·예산·예상 묶음 수를 표시한다. 계정 연결이 없으면 연결 설정으로 안내하며 자동 전송하지 않는다.
4. **생성하기**를 누른 뒤 AI 분석을 시작한다. 진행률, 취소, 실패 위치, 재개를 제공한다. 등록 자체로 과금되는 호출을 시작하지 않는다.
   최초 계획에는 본문 묶음 수와 추가 관계 검토 발생 가능성을 표시한다. 관계 후보 수는 본문 분석 뒤 확정하여 진행 상태를 갱신하며 확정 비용처럼 안내하지 않는다.
5. 결과를 지도에서 미리 본다. 실제 구조 위에 AI 주제와 점선 관계를 제안으로 표시하고, 선택 시 이유·근거·원문 위치를 보여준다.
6. **지도에 반영** 또는 개별 제외 후 반영한다. 문서 본문은 변경하지 않는다. 생성 취소 시 원래 지도와 사용자 배치를 보존한다.
7. 나중에 선택한 경우 관계 지도의 **AI로 지도 생성/업데이트**에서 같은 과정을 시작한다. 기존 수동 관계·배치는 자동 삭제하거나 초기화하지 않는다.

## 지도와 범례

- 루트는 실제 프로젝트 ID에서 만든 로컬 노드다. 등록된 파일만 문서 노드로 표시하고 미등록 파일을 읽지 않는다.
- 실제 Markdown 소제목은 기존 Section ID를 사용하고 모든 깊이를 문서 오른쪽 열에 나열한다. 깊이는 카드의 H1/H2 표시와 들여쓰기로 구분한다.
- 제목 없는 문서는 문서 노드만으로도 표시한다. AI는 근거 범위를 가진 요약 주제 카드를 제안할 수 있고 ‘AI 요약 주제’ 배지를 붙인다. 실제 Markdown 제목과 혼동시키지 않는다.
- 문서별 소제목 접기/펼치기·검색·원문 이동을 제공한다. 접힌 섹션의 관계는 문서 카드에 모아 연결 수를 표시하고 원래 endpoint ID는 보존한다.
- 실선: 프로젝트→문서, 문서→소제목/주제의 포함 구조. 이 선은 구조에서 파생하며 관계 삭제 동작으로 원문을 변경하지 않는다.
- 점선: 문맥 관계. AI 제안/확정/직접 연결/원문에서 발견된 관계의 출처와 상태는 배지·상세정보로 구분한다. AI 관계를 수락해도 포함 구조 실선으로 바꾸지 않는다.
- 범례: **실선 — 문서 구조 / 점선 — 문맥 관계 / AI 제안 — 미확정**. 오른쪽 위 고정 오버레이로 표시하고 접기 상태는 로컬에 저장한다. 색상만으로 의미를 구분하지 않는다.
- 원문 링크는 링크 문구를 우선 사용한다. ‘여기’, URL 같은 의미 없는 문구는 ‘참조’로 표시하고 AI 제안 또는 사용자가 의미를 보완한다. 원문 URL·출처·행은 상세정보에 남긴다. 원문 파생 관계의 표시 이름 변경은 로컬 별칭이며 원문 링크를 수정하지 않는다.

## 배치와 선 경로

- 초기 열 x 좌표는 루트 0 / 문서 360 / 소제목 760px, 기본 카드 폭 230px이다. 실제 측정 높이로 문서별 묶음을 겹치지 않게 배치한다. 이후 사용자가 옮긴 좌표를 우선한다.
- 문서·섹션을 옮겨도 다른 카드를 강제로 움직이지 않는다. 전체 자동 정렬은 명시 버튼으로만 실행하고 확인 후 저장한다. 새 문서/주제는 기존 배치를 유지한 빈 영역에 배치한다.
- 이동 중에는 로컬 좌표를 우선해 주기적인 서버 새로고침으로 카드가 되돌아가지 않게 한다. 저장 실패 시 편집 좌표를 유지하고 재시도와 미저장 표시를 제공한다.
- 유한한 좌표만 저장한다. 프로젝트 ID와 안정적인 노드 ID로 저장하고 원문 삭제/ID 변경 시 좌표는 비활성 보존하되 다른 노드에 재할당하지 않는다.
- 경로는 실측 카드 사각형에 16px 여백을 더한 장애물을 사용한다. 출입 포트에서 바깥으로 나온 뒤 12px 격자의 직각 A*로 탐색한다. 실제 선분과 사각형의 교차를 마지막에 재검증한다.
- 기본 연결 포트는 오른쪽 출발/왼쪽 도착이다. 역방향·같은 열 관계에는 위/아래 포트도 고려한다. 길이·꺾임·기존 선과 겹침/교차를 비용으로 줄인다. 라벨도 카드 밖의 빈 선분에 배치한다.
- 배선은 Web Worker에서 수행하고 요청 버전으로 이전 결과를 폐기한다. 드래그 중에는 위치를 즉시 반영하고 배선 요청을 최대 100ms 간격으로 갱신하며 드래그 종료 시 확정 계산한다.
- 탐색 상한은 선당 50,000개 상태이며, 초과 시 외곽 여백을 확장한 한 번의 재탐색을 수행한다. 여전히 실패하면 잘못된 직선을 그리지 않고 ‘경로 계산 보류’를 표시한다. 이전 경로는 현재 장애물에 대해 유효한 경우에만 사용한다.
- 카드가 겹쳐 통로가 없으면 겹침 상태와 이동 안내를 보여준다. 모든 선의 교차를 완전히 없앤다고 보장하지 않는다.
- 초기 성능 목표는 실측 카드 300개/선 500개의 배선 2초 이내 및 드래그 중 UI 응답 유지다. 실제 측정값을 검증 문서에 기록하며 초과 시 진행 표시와 취소를 유지한다. 노드/관계를 조용히 버리지 않는다.

## AI 분석과 저장 계약

- 파일 등록은 로컬 동작이다. 전송 동의·범위 확인·생성 시작을 분리한다. 요청 중 프로젝트 전환, 초안 발생, 문서 revision 변경 시 결과 반영을 차단한다.
- #19의 예산 계산·스냅샷·취소/재개·호출별 사용량·완료 묶음 재사용을 공통 실행부로 추출한다. 문서 수정 요청과 지도 생성의 출력 계약·캐시 namespace는 분리한다.
- 모델과 출력 형식은 main에서 고정한다. 지도 응답에는 원문 수정 명령이나 임의 좌표를 받지 않는다. 실제 문서/섹션 노드는 플랫폼이 만들고 AI는 요약 주제, 검색 키워드, 의미 관계, 근거를 반환한다.
- 근거는 snapshot source ID·revision·원문 내 범위·일치하는 인용문으로 검증한다. 관계 양쪽 endpoint의 소유 문서와 근거가 모두 실제 제공된 맥락에 있어야 한다. 다른 프로젝트·제외 문서·가짜 ID·범위 초과를 거부한다.
- 첫 분석은 포함 본문 전체를 묶음별로 읽는다. 다음 단계는 링크/제목/AI 검색 키워드로 다른 문서의 관련 섹션 후보를 찾고 양쪽 원문을 같이 검토한다. 키워드 후보는 섹션당 상위 3개를 사용하되 기존 링크 후보는 별도로 모두 처리한다. 후보 수·검토 범위·누락 사유를 표시한다.
- 모든 섹션 쌍을 전수 비교하지 않는다. 전수 비교 비용 O(N²)을 숨기지 않고 ‘전체 본문 분석 + 후보 관계 검토’로 표시한다.
- 생성 결과는 기존 Proposal과 별도의 MapDraft로 저장한다. 지도 반영은 동일 draft ID로 중복 적용을 막고 트랜잭션으로 처리한다. 사용자 확인 전 기존 관계·배치를 변경하지 않는다.
- 동일 문서 revision·근거 범위·관계 종류·endpoint가 같은 제안은 합친다. 충돌하는 관계는 덮어쓰지 않고 별도 검토 항목으로 남긴다. 수동 별칭은 AI 재생성보다 우선한다.

## 범위 밖

Mermaid/기존 프로젝트 흐름 탐색·편집은 유지한다. 관계만으로 실행 순서를 확정하지 않는다. 이번 지도에서 원문 소제목 편집·파일 이동·자동 코드 수정·벡터 DB·새 유료 제공자·자동 업데이트는 추가하지 않는다. 이슈 #3/#4는 별도다.

## 완료 기준

등록 → 동의 → 범위 확인 → AI 생성 → 지도 미리보기 → 반영의 전체 흐름을 임시 프로젝트/가짜 제공자로 검증한다. 좌→우 구조·이동/재시작 복원·장애물 회피·범례·근거 이동·부분 실패/취소/재개·원문 보존·기존 프로젝트 호환을 확인한다. lint/format/typecheck/관련 테스트/build/Electron E2E와 macOS·Windows CI를 통과한 뒤 전달한다. 실계정 유료 추론은 일반 검증에 포함하지 않는다.
