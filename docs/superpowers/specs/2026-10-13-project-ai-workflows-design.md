# 프로젝트 섹션과 AI 검토 흐름 설계

상태: 대화에서 기능 설계 승인 완료, 구현 전 문서 검토용. 날짜: 2026-10-13.

## 목표와 범위

사용자가 승인한 목표는 여러 로컬 프로젝트를 구분해 작업하고, AI가 문서 관계와 거절 사유를 검토하며, 실제로 보고된 사용량을 확인하는 것이다. 기존 문서·미저장 초안·대화·제안 수락/거절 이력을 보존한다. Gemini, Claude CLI 제공자 추가, 자동 결제·한도 초기화, 공개 전환은 포함하지 않는다.

독립적으로 검증·리뷰할 수 있도록 아래 네 작업을 각각 구현 계획과 PR로 나눈다. 공통 계약은 해당 기능의 PR에서 필요한 만큼만 추가한다. 대규모 파일 구조 개편이나 새 상태 관리 라이브러리는 도입하지 않는다.

## 개발 절차

- 저장소는 비공개를 유지하고 이슈 → 기능 브랜치 → Conventional Commits → PR → CI → 리뷰 → squash merge 순서를 따른다.
- 현재 기준은 `feat/open-source-claude`의 `4fc5576`이다. PR #5가 미병합이므로 설계 PR은 해당 브랜치를 base로 한다. 구현 PR은 기반 기능 PR을 명시하는 순차 의존 방식으로 만들고, 선행 PR이 병합되면 base를 갱신한다. `main` 직접 push, force push, 승인 없는 선행 PR 병합은 하지 않는다.
- 구현 순서: #2 프로젝트 섹션 → #6 관계 제안 → #7 사용량 → #8 거절 후 대화. 브랜치 이름은 `feat/2-project-sections`, `feat/6-ai-relationships`, `feat/7-ai-usage`, `feat/8-rejection-followup`으로 한다.
- 커밋 예: `feat(projects): 프로젝트별 섹션과 전환 추가`. PR 설명에 연결 이슈, 최종 동작, 검증 결과, 한계, AI 도움 범위를 한국어로 적는다. 기존 이슈의 완료 조건을 모두 충족하기 전에는 닫지 않는다.

## 1. 프로젝트별 섹션 — #2

사이드바에 등록된 프로젝트를 접고 펼치는 섹션으로 표시한다. 프로젝트 제목 선택은 활성 프로젝트를 전환하며 해당 문서·대화·제안·관계 지도를 함께 표시한다. 펼치기만 하는 조작과 활성화 조작을 분리한다. 비활성 프로젝트의 문서 항목을 선택하면 그 프로젝트로 전환한 뒤 해당 문서를 연다. 동시에 AI 요청을 실행하는 프로젝트는 하나다.

main에서 사용자가 폴더 선택기로 등록한 프로젝트만 관리한다. canonical 경로로 중복 등록을 막고, renderer에는 임의 경로를 열 수 있는 API 대신 등록 ID를 받는 전환 API를 제공한다. 목록에는 프로젝트 ID·이름·등록 경로·마지막 선택 시각을 저장한다. 기존 `settings.json`의 마지막 `root`는 첫 프로젝트로 이관하고 AI 제공자별 설정은 유지한다. 이름 변경은 목록에도 반영한다.

프로젝트별 선택 문서·보기·접힘 상태·대화 입력과 문서별 편집 초안을 로컬에 저장한다. 초안은 문서 ID와 기준 revision을 포함하며 원본 Markdown을 덮어쓰지 않는다. 전환과 재시작 후 복원하고, 외부 문서가 바뀌었다면 충돌을 표시해 초안을 보존한다. 명시적 저장 또는 초안 버리기 전에는 삭제하지 않는다. 현재 편집기의 초안 소유권을 상위 상태와 연결해 컴포넌트 전환으로 유실되지 않게 한다.

등록 해제는 목록에서만 숨기며 실제 폴더·DB·초안은 삭제하지 않는다. 활성 프로젝트 해제 시 다른 등록 프로젝트를 선택하거나 빈 화면으로 이동한다. 폴더 누락·접근 실패는 해당 항목에 표시하고 나머지 프로젝트 사용을 허용한다. AI 요청 중 전환과 활성 프로젝트 해제는 차단한다. 설정은 임시 파일 후 rename으로 저장하며 손상된 설정 파일은 보존하고 복구 가능한 항목을 사용한다.

검증: 구버전 설정 이관, 동일 경로 중복, 누락 폴더, 프로젝트 간 데이터 격리, 미저장 초안·대화 입력 왕복 전환 및 재시작 복원, 외부 수정 충돌, 요청 중 전환 차단을 테스트한다.

## 2. AI 관계 지도와 커스텀 편집 — #6

관계 지도에 ‘AI로 관계 검토’를 추가한다. 사용자가 검토 문서를 선택하고 전송할 맥락을 확인·제외한 뒤 요청한다. 큰 프로젝트는 기존 맥락 크기 제한을 지키며 빠진 문서를 명확히 표시한다. 읽기 대상은 저장된 문서이며 미저장 변경이 있는 대상 문서는 저장 후 검토하도록 안내한다.

기존 구조화된 제안 계약에 관계 제안을 추가한다. 제안에는 출발·도착 문서 ID, 연결 유형, 근거, 양쪽 문서의 기준 revision을 넣는다. 전달된 문서에 속하는 대상만 허용하며 같은 문서로 연결하거나 존재하지 않는 ID를 사용하는 응답은 거부한다. 이 단계의 AI 관계 제안은 문서 단위로 한정한다. 기존 수동 섹션 연결은 유지한다.

제안 목록과 그래프에서 AI 제안을 확정 관계와 구분해 표시한다. 사용자는 개별 제안을 수락·거절할 수 있으며 수락 전 실제 관계를 변경하지 않는다. 수락 시 문서 존재·revision·동일 방향과 유형의 중복 연결을 다시 확인한다. 오래된 제안은 재검토 상태로 남기고 자동 적용하지 않는다. 관계 저장과 수락 이력은 한 DB 트랜잭션으로 처리한다. 기존 문서·결정 제안의 저장 형식과 이력은 계속 읽을 수 있어야 한다.

수동 추가·연결 유형 수정·삭제를 지원한다. AI가 생성한 연결도 같은 편집 기능을 사용한다. 삭제는 선택한 관계에만 적용하며 전체 관계를 자동 재생성하거나 기존 연결을 일괄 제거하지 않는다. 방향·유형·근거가 읽히는 기존 그래프 스타일과 키보드 focus 툴팁을 유지한다.

검증: 제외된 근거, 존재하지 않는 ID, 자기 연결, 중복, revision 변경·문서 삭제 후 수락, 수락 중 오류의 원자성, 기존 제안 호환성, 수동 편집 및 재시작 후 이력 보존을 확인한다.

## 3. AI 사용량과 남은 한도 — #7

AI 패널에 사용량 버튼과 상세 화면을 둔다. 요청별 제공자·모델·시각·상태와 보고된 입력/출력/캐시 토큰을 로컬에 저장하고, 프로젝트 누적량을 제공자별로 표시한다. 캐시 토큰은 입력의 포함 관계를 제공자별로 처리하여 중복 합산하지 않는다. 계정 한도는 프로젝트 누적량과 분리한다. 사용량이 기록되지 않은 과거 요청은 0으로 추정하지 않는다.

Codex는 설치된 CLI에서 생성한 프로토콜과 공식 문서를 기준으로 `thread/tokenUsage/updated`를 수집하고 `account/rateLimits/read`로 계정 한도를 조회한다. 스레드 누적량을 동일 요청에서 반복 합산하지 않고 요청 ID를 기준으로 최신 보고값을 갱신한다. 다중 한도가 있으면 각각 기간·남은 비율·초기화 시각을 표시하고 기존 단일 한도 응답도 지원한다. 계정 식별자와 인증 토큰은 renderer나 사용량 기록에 포함하지 않는다.

Claude API는 Messages 응답의 `usage`와 rate-limit 응답 헤더를 읽는다. 분당 요청/토큰 한도와 초기화 시각을 표시하며 이를 Claude 구독 잔량이나 API 결제 크레딧으로 표현하지 않는다. 일반 API 키에서 확인할 수 없는 잔액은 ‘제공자가 제공하지 않음’으로 표시한다. 실패·취소·형식 오류가 있어도 제공자가 사용량을 보고했다면 기록하고, 보고가 없으면 ‘확인 불가’로 남긴다.

조회 실패와 미지원은 AI 요청을 막지 않는다. 마지막 조회 시각과 오류·오래된 상태를 표시하고 새로고침을 지원한다. 값이 없거나 잘못된 경우 0으로 바꾸지 않는다. ‘확인 불가’에는 사용자가 이해할 수 있는 사유를 함께 표시한다. 사유는 과거 기록 없음·제공자 미지원·로그인 방식 미지원·인증 확인 필요·연결 실패·제공자 응답 누락·응답 값 오류로 구분한다. 마지막 값이 있다면 마지막 확인 시각과 새로 조회하지 못한 이유를 표시하며 현재 값처럼 표현하지 않는다. 인증정보·계정 식별자·서버 원문 오류는 노출하지 않는다. 한도 조회는 읽기 전용이며 추론 요청, 크레딧 구매, 초기화 사용, 타인에게 알림 전송을 수행하지 않는다. 공급자 전환 시 이전 공급자의 한도를 현재 공급자의 것으로 표시하지 않는다.

검증: 실제 프로토콜 형태의 mock 이벤트/응답, 중복 이벤트, 캐시 합산, 누락·비정상 숫자, 실패와 취소, 계정 한도 다중/단일 응답, 공급자 변경, 새로고침 실패를 테스트한다. 실계정 한도 조회는 읽기 전용으로 확인하고 유료 생성은 별도 필요가 있을 때만 실행한다.

## 4. 거절 사유 전송과 후속 대화 — #8

제안의 거절 버튼은 즉시 거절하지 않고 이유 입력 영역을 연다. 기존 ‘거절 확정’은 ‘보내기’로 변경하며 취소 시 제안 상태와 이력을 그대로 둔다. 이유 없이 보내면 거절만 기록하고 AI 호출은 하지 않는다. 이유가 있으면 해당 제안·사유를 거절 이력과 사용자 대화에 한 번 기록한 후 대화 탭으로 이동해 AI가 이유를 검토한다.

AI 맥락에는 거절한 제안의 요약, 사유와 명시적으로 선택한 문서·허용된 근거를 포함한다. 과거 제안의 전체 내용 때문에 제외된 문서가 다시 외부 전송되지 않게 맥락을 구성한다. 응답은 질문·설명 또는 새로운 보완 제안일 수 있다. 거절 이력은 유지하고 후속 제안을 자동 수락하지 않는다. 기존 대기 제안 수정 기능과 별도로 거절 피드백 컨텍스트를 지원한다.

main에서 제안 상태·프로젝트 범위·요청 중 여부·사유 길이를 검증하고, 피드백 ID로 거절/메시지 기록을 멱등 처리한다. 네트워크 실패 시 사유와 거절 상태를 보존하고 동일 피드백의 응답 재요청을 지원한다. 재시도는 거절이나 사용자 메시지를 중복 생성하지 않는다. 전송 중에는 중복 클릭을 막으며, 실패 후 편집·재시도 또는 일반 대화 계속하기가 가능해야 한다.

검증: 거절 클릭 후 취소, 빈 사유, 유효 사유와 후속 답변, 실패 후 재시도·재시작, 중복 전송, 이미 처리된 제안, 요청 중 조작, 제외된 문서의 피드백 맥락 누출을 확인한다.

## 검증과 패키지

각 구현 PR에서 가까운 서비스/단위 테스트를 먼저 실행하고 타입 검사·빌드·Electron E2E를 수행한다. 프로젝트별 왕복 전환, AI 관계 제안 검토, 사용량 상태, 거절 사유 전송을 합성 데이터로 캡처한다. 개인 문서·키·실계정 대화는 PR과 이미지에 포함하지 않는다. 네 기능 통합 후 최종 앱/DMG를 갱신하고 DMG에서 별도 경로로 복사한 앱과 내부 상대 링크를 확인한다. 사용자 앱 교체 전 실행 중 미저장 작업을 확인하며 테스트 목적으로 실제 프로젝트를 변경하지 않는다.

## 조사 근거

- [기여 규칙](../../../CONTRIBUTING.md): 기능 브랜치, Conventional Commits, 한국어 PR, CI와 데이터 경계.
- [OpenAI 공식 App Server 문서](https://developers.openai.com/codex/app-server): 사용량 이벤트와 계정 한도 조회. 설치된 CLI의 생성 타입에서도 해당 메서드와 필드를 확인했다.
- [Claude Messages 응답](https://platform.claude.com/docs/en/api/messages/create): 입력·출력·캐시 사용량 필드.
- [Claude rate limits](https://platform.claude.com/docs/en/api/rate-limits): 응답 헤더의 한도와 초기화 시각. 계정 잔액과 다른 값이다.
