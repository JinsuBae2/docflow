# 프로젝트 흐름 보기 검증 — #18

기준: eec96c9. 브랜치: feat/18-project-flows.

## 구현 범위

- main에서 Markdown AST의 여러 문서·중첩 코드 블록과 프로젝트 내부 정의 파일 링크를 색인한다. 문서·섹션·블록 제목·형식·원문 경로·행을 목록에 표시한다.
- Mermaid flowchart/graph, sequenceDiagram, stateDiagram(-v2)을 로컬에서 렌더링한다. 관계 지도와 구분되는 설명과 검색·새로고침·원문 코드를 제공한다. AI 생성은 기존 요청·제안·수락 경로를 유지한다.
- `.mmd`/`.mermaid`를 포함한 연결 정의 파일은 안전한 상대 경로·파일 식별자로 중복을 제거해 읽기 전용으로 보여준다. 미지원 PlantUML/DOT/D2는 어댑터 목록과 원문 보기만 제공한다. 심볼릭 링크·프로젝트 밖 파일·제외 경로는 접근하지 않고 사유를 표시한다.
- Markdown 코드의 원문 위치로 이동해 강조한다. 정의 파일은 앱 안에서 코드를 열람하며 참조 문서로 이동한다.
- 시각 편집은 닫힌 최상위 Mermaid 펜스 안의 사각 단계·무라벨 화살표·방향에 한정한다. 단계 추가/삭제/이름 변경, 핸들 드래그/키보드 연결, 연결 삭제를 제공한다. 복잡한 문법·주석·중첩 블록은 손실 없이 읽기 전용으로 유지한다.
- 저장은 main의 프로젝트·흐름 ID·전체 원문 revision·문서 초안을 검증하고 선택한 코드 범위만 조합한다. 기존 파일 journal로 커밋하며 원본 CRLF·펜스·비선택 본문·블록·문서 메타데이터를 유지한다. 충돌 시 원문을 덮어쓰지 않고 편집 화면을 유지한다.
- Mermaid strict 모드와 실행 명령·URL·HTML·config 차단을 적용한다. 정상 라벨·메시지 안의 Click/callback은 허용하며 실제 명령 위치는 차단한다.

## 경계와 제한

- 흐름 ID는 문서/경로·언어·코드 fingerprint와 동일 코드의 등장 순서에서 만든다. 주변 본문 변경에는 안정적이며 코드 자체를 수정하면 새 ID를 선택한다. 동일 코드 중복의 삽입/삭제·재정렬은 식별이 달라질 수 있다.
- 위치는 자동 배치하며 Mermaid에는 단계·연결·방향을 저장한다. 별도 정의 파일과 복잡한 문법의 시각 편집은 제공하지 않는다.
- Mermaid 렌더 한도는 50,000자·500개 연결, 기본 편집 한도는 100개 단계·200개 연결이다. 원문은 한도로 삭제하거나 잘라 저장하지 않는다. 정의 파일 읽기는 기존 문서 파일당 2MB 경계를 사용한다.
- 실제 개인 문서·유료 AI 추론·설치 패키지 재생성은 사용하지 않았다. macOS·Windows GitHub 결과는 PR Checks에서 확인한다. 큰 AI 맥락 분석은 #19에서 진행한다.
