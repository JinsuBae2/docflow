# 비공개 저장소 준비와 Claude 연결 검증

## 범위

기존 앱을 첫 Git 기준선으로 기록하고, 한국어 공개 준비 문서·MIT 라이선스·외부 고지·기여 양식·GitHub 운영 규칙과 Claude API 연결을 추가했습니다. 사용자의 후속 지시에 따라 저장소는 PRIVATE으로 유지합니다. 공개 릴리스는 만들지 않습니다.

## 로컬 검증

- 타입 검사 통과.
- 코드 커밋 ee84b8b의 원격 macOS·Windows CI 및 Conventional Commit PR 제목 검사 모두 통과. 원격 CI는 새 checkout과 npm ci부터 실행했습니다.
- 단위·통합 테스트 34개 통과, 실계정 opt-in 4개 건너뜀.
- 새 Claude 제공자·설정·키 저장 테스트는 구현 전 실패를 확인한 뒤 통과했습니다. 시간 초과 시 실제 요청 중단도 확인했습니다.
- Electron E2E 전체 4개 통과. 제공자 선택·모델 저장·재시작 복원, Claude 제안 수락 전 원본 불변, 수락 후 결정 반영, 가져오기·초안·기존 이력을 검증했습니다.
- 원격 macOS의 툴팁 실패는 문서 패널의 독립 스크롤이 AI 패널 툴팁까지 닫는 문제였습니다. CI 이벤트 로그로 원인을 확인하고, 로컬 회귀 테스트 실패를 재현한 뒤 툴팁의 조상 스크롤 영역에만 닫기 동작을 적용했습니다. 검사 중복을 줄이기 위해 작업 브랜치는 PR에서만 검사합니다. 이후 원격 결과는 GitHub Actions에서 확인합니다.
- 프로덕션 빌드 및 macOS arm64 패키징 통과. 네트워크 제한으로 패키징 첫 시도만 실패했으며 완료된 빌드로 패키징을 재실행했습니다.
- 갱신한 패키지의 Electron/SQLite/preload/관계 지도 실행 검증 통과.
- 샘플 프로젝트 화면 4장 촬영 및 시각 확인. 실제 문서·키·가짜 모델 목록은 포함하지 않았습니다.
- README 로컬 링크와 YAML 구문 검사 통과.
- production 의존성 취약점 조회 0건. 라이선스 고지는 238개 production 항목과 Electron 런타임 기준으로 생성했습니다.

## 실제 계정 검증과 한계

제한된 실행 환경에서는 Claude CLI 로그인 없음으로 표시됐으나, OS 인증 저장소에 접근 가능한 환경에서 공식 CLI 로그인을 확인했습니다. 임시 폴더에서 safe-mode, 빈 tools, 빈 MCP 설정, 설정 로딩 해제, 세션 저장 해제를 적용해 합성 인사 요청을 1회 실행했고 구조화된 JSON 응답에 성공했습니다. 확인한 모델은 claude-opus-5-5입니다. 사용자 문서나 인증정보를 응답 기록에 포함하지 않았습니다.

이 결과는 공식 CLI 자체의 실계정 연결 확인입니다. 앱에 구현한 Anthropic API 연결은 ANTHROPIC_API_KEY가 없어 실계정 생성 성공을 검증하지 않았습니다. 앱의 API 모델 조회·생성 smoke test는 명시적 환경 변수로 실행하도록 추가했습니다. 일반 CI의 Claude 응답은 가짜 API입니다.

Claude 응답은 완료 후 한 번 검증하며 토큰 단위 스트리밍은 제공하지 않습니다. 수락 전에는 문서에 적용되지 않습니다. API 키는 일반 설정에 저장하지 않고 renderer로 반환하지 않습니다. 안전하지 않은 OS 키 저장소는 거부합니다.

별도 읽기 전용 리뷰에서 Critical/Important 발견 사항은 없었습니다. 경미한 후속 과제는 활성 Claude 키 삭제 후 안내를 저장하지 않고 닫을 때 메인 연결 표시가 이전 상태일 수 있다는 점입니다. AI 연결 확인 버튼으로 갱신할 수 있으며 실제 요청은 인증 검사를 거칩니다. GitHub 이슈로 추적합니다.

서명·공증, Windows/Intel Mac 실기기, 앱의 Claude API 실계정 생성은 미검증입니다. 공개 전 전용 보안 신고 경로를 정해야 합니다.

## 설치 앱 실행 오류 수정 (2026-10-13)

응용 프로그램에 설치한 앱에서 `icudtl.dat not found in bundle` 오류와 Helper 프로세스 종료를 재현했습니다. 기존 검증은 빌드 폴더의 앱만 실행했으므로 DMG 복사 오류를 발견하지 못했습니다.

DMG 생성 시 Node.js `cpSync`가 프레임워크의 상대 심볼릭 링크를 빌드 폴더의 절대 경로로 변환했습니다. `verbatimSymlinks: true`로 링크를 보존하도록 수정했습니다. 회귀 테스트는 원본 폴더를 삭제한 뒤 복사본에서 리소스를 읽으며, 수정 전 실패·수정 후 통과를 확인했습니다. DMG 전용 테스트이므로 macOS에서 실행합니다.

- 타입 검사와 관련 회귀 테스트 통과.
- 새 DMG 무결성 검사 통과. 내부 링크 14개가 모두 상대 경로이고 앱 내부에서 해결됨을 확인.
- DMG에서 별도 경로로 복사한 앱의 Electron/SQLite/preload/문서/관계 지도 UI 검증 및 화면 캡처 통과.
- 기존 설치 앱을 로컬에 백업하고 `/Applications/Docflow.app`을 교체. 일반 앱 실행에서 기존 프로젝트·대화가 표시되는 것을 접근성 트리와 화면 캡처로 확인. 사용자 데이터는 삭제하거나 초기화하지 않음.

앱 코드와 빌드 출력은 변경하지 않았으며 DMG를 재생성했습니다. Apple 개발자 서명·공증은 여전히 적용하지 않았습니다.
