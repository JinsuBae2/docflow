# 원본 문서 탐색·등록 검증 — #15

기준: `c3b8016`의 main에서 `feat/15-docs-discovery` 브랜치 생성.

## 동작과 경계

- 프로젝트 폴더 열기·드롭 후 하위 docs 후보를 탐색하고 사용자 선택으로만 원본 Markdown을 등록한다. 전체/개별 선택, 취소, 파일·폴더 직접 선택, 수동 재탐색을 제공한다.
- 원본 연결 문서는 상대 경로·ID·revision과 메타데이터로 관리한다. 등록 시 본문·CRLF·기존 YAML을 유지하며 식별자 주석을 삽입하지 않는다. 기존 앱 관리 문서와 사본 가져오기는 유지한다.
- 원본 편집 화면에 저장 경로와 `원본에 저장` 동작을 표시한다. AI 수정안도 검토·수락 전에는 원본을 바꾸지 않는다.
- 중복·미지원·과대 파일과 심볼릭 링크는 사유를 표시한다. 프로젝트 밖 경로와 앱 데이터·의존성·빌드 경로는 거절한다. macOS의 프로젝트 상위 `/var` 경로 별칭은 허용하되 내부 심볼릭 링크 검사는 유지한다.
- 등록은 30개·파일당 2MB·전체 10MB로 제한한다. 탐색은 10,000개 항목·500개 후보·20단계 깊이로 제한하고 잘린 범위를 안내한다. 등록 전 전체 묶음의 크기·revision·중복을 검증하고 단일 DB 트랜잭션으로 기록한다.
- 삭제·이동한 파일은 경고와 함께 목록에서 제외하되 메타데이터·이력은 보존한다. 경로 이동 자동 추적은 제공하지 않는다.
- 연결 문서 섹션 ID는 문서 ID와 제목·레벨·동일 제목의 등장 순서로 결정한다. 본문 수정과 재시작에 안정적이며 제목 변경·동일 제목의 순서 변경은 재연결 검토가 필요할 수 있다.

## 검증

| 검사 | 결과 |
| --- | --- |
| lint / format:check / typecheck | 통과 |
| 전체 단위·통합 테스트 | 66개 통과, live API 선택 실행 5개 제외 |
| build | 통과 |
| 전체 Electron E2E | 11개 통과 |
| 독립 전체 브랜치 리뷰 | 원본 문서 AI 수정안 검증 문제 1건 수정, 회귀 테스트 통과 |

새 통합 테스트는 실제 임시 파일·디렉터리·SQLite 저장소로 발견/취소, 한글·공백·복수 docs, 원본 보존, 재시작 ID, 초안·관계·결정, 외부 수정·삭제·이동, 경로 경계, 일괄 제한, AI 수정안 등록/수락을 검사한다. E2E는 네이티브 선택 창의 반환값만 합성하며 실제 앱 UI와 Chromium 폴더 드롭으로 등록·초안 복원·원본 저장·미리보기 만료를 검증한다. 등록 화면의 합성 데이터 캡처를 육안으로 확인했다.

실패를 확인한 뒤 구현·수정했다: 신규 기능 부재, macOS 경로 별칭 처리, 체크박스 CSS 충돌, 원본 연결 문서의 기존 섹션 주석 검사. 대용량 등록은 파싱 전 한도 검증으로 불필요한 처리를 줄였으며 이후 전체 테스트가 통과했다.

최종 빌드 E2E 실행에서는 기존 사용량 테스트의 설정 모달이 클릭을 가로막는 대기 실패가 1회 발생했다(나머지 10개 통과). 해당 테스트는 코드 변경 없이 재실행해 4.1초에 통과했다. 앞선 전체 실행은 11개 모두 통과했으며, 이 간헐적 실패는 원본 등록 화면 테스트가 아니다.

실제 개인 문서·유료 AI 요청·설치 패키지 생성은 사용하지 않았다. GitHub macOS·Windows 결과는 PR Checks에서 확인한다. 문서 링크 자동 관계(#16)는 후속 범위다.
