# 프로젝트 관계지도 기반 검증 — 2026-10-14

대상: 이슈 #29, `feat/project-map-layout`, 기준 커밋 `9d5209b`. 승인 계획의 PR A(Tasks 1–3) 범위다.

## 구현

- 프로젝트 루트 → 등록 문서 → 실제 소제목의 3열 카드와 의미 관계를 표시한다. 기존 문서·섹션 ID와 원문을 유지한다.
- 카드 드래그·방향키 이동, 프로젝트별 좌표 저장, 문서별 접기, 검색, 명시적 자동 정렬과 고정·접이식 범례를 제공한다.
- 저장 요청은 순서대로 실행하고 버전으로 이전 조회 결과의 덮어쓰기를 방지한다. 실패한 배치는 로컬 복구 데이터로 남기며 재시도를 제공한다.
- 실측 카드에 16px 여백을 둔 12px 격자 A* 배선을 Worker에서 계산한다. 선별 탐색 상한은 총 50,000 상태이며 외곽 확장은 한 번이다. 막힌 통로에는 카드를 가로지르는 대체 직선을 그리지 않는다.
- 드래그 중 최신 좌표를 100ms 간격으로 전달한다. 캐시 경로는 현재 포트와 장애물에 맞춰 재검증하고 이전 버전의 Worker 응답을 무시한다.

## 검증 범위

- `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run build`: 통과.
- `npm test`: 103개 통과, 실계정 제공자 테스트 5개 건너뜀.
- `npx playwright test`: 15개 통과, 기존 `usage.spec.ts`의 Claude 설정 저장 대기 1개 실패. 실패 항목 단독 재실행은 통과(3.1초). 전체 실행이 한 번에 모두 통과했다고 주장하지 않는다.
- 단위·통합: 지도 구조, 원문 불변, 소유 프로젝트·좌표 검증, 저장·재시작, 삭제된 접기 ID, 배치, 장애물 여백, 역방향·자기 연결, 탐색 예산, 움직인 포트, 격자에 정렬된 직선 연결.
- Electron: 실제 연결점 드래그, 카드·라벨 교차 검사, 관계 수정, AI 제안 보존, 연속 드래그 중 Worker 전송과 선 유지, 방향키 이동 저장, 좌표·접기·범례 재시작 복원.
- 독립 리뷰의 삭제된 접기 ID, 드래그 중 배선 지연, 방향키 저장 누락, 직선 endpoint 충돌 네 건을 수정하고 회귀 검증했다.
- 예제 프로젝트 화면: `docs/images/project-map-layout.png`. 실제 사용자 파일·인증정보·AI 추론 요청을 사용하지 않았다.

## 성능과 한계

로컬 Node에서 10열×30행의 300개 카드와 인접 카드 연결 500개를 `routeEdges()`로 계산한 결과 86ms, 500개 경로 준비 완료였다. 이는 배선 함수의 합성 측정이며 Worker 전달·화면 렌더링 시간이나 모든 밀집 배치의 성능을 보장하지 않는다.

저장 실패 복구 UI와 오래된 Worker 응답 폐기는 구현을 확인했으며, 강제 IPC 실패·Worker 응답 순서 뒤집기를 주입하는 Electron 테스트는 추가하지 않았다. 겹친 카드·막힌 포트·라벨을 배치할 공간이 없는 경우 경고와 관계 목록으로 확인한다. 전체 맞춤 화면에서는 소제목 수에 따라 축소되므로 확대하거나 문서를 접어 탐색한다.

AI 등록 안내·예산 확인·본문 분석·근거 기반 지도 생성·미리보기 적용은 승인 계획의 후속 PR B(Tasks 4–7)다. DMG 재배포와 자동 업데이트는 이번 범위에 포함하지 않는다.
